# Setup Notes

How I built the honeypot, in order, including what went wrong.

## 1. Oracle Cloud account
- Created an Oracle Cloud Free Tier account with **US West (Phoenix)** as the home region.
- Set a **$1 budget alert** in Billing & Cost Management so I'd get an email if anything ever started costing money.

**Problem:** Sign-in kept failing with an error page.

**Fix:** Signed in from an incognito window using the link in Oracle's welcome email.

## 2. The server
- Shape: **VM.Standard.A1.Flex** (Ampere ARM), **2 OCPU / 12 GB RAM**
- Image: **Ubuntu 26.04 LTS (aarch64)**
- Boot volume: **200 GB** (T-Pot logs fill disk quickly)
- SSH key pair generated by Oracle, private key stored only in `~/.ssh` on my laptop

**Problem:** Most guides say the free ARM allowance is 4 OCPU / 24 GB. Oracle's current docs say **2 OCPU / 12 GB**.

**Fix:** Checked the official docs and sized the VM to 2/12 so it stays free. T-Pot lists 8-16 GB RAM, so 12 GB fits.

**Problem:** The "Assign a public IPv4 address" toggle was grayed out in the create wizard.

**Fix:** Created the instance, then added an ephemeral public IP on the VNIC afterward.

## 3. Firewalls
Oracle has two layers, and both had to be configured.

**Cloud firewall (VCN Security List) ingress rules:**
| Source | Protocol | Ports | Purpose |
|---|---|---|---|
| 0.0.0.0/0 | TCP | 1-64000 | Honeypots |
| 0.0.0.0/0 | UDP | 1-64000 | Honeypots |
| My IP /32 | TCP | 64294-64297 | Admin SSH and web dashboard (me only) |

**Host firewall:** Oracle's Ubuntu image ships with iptables rules that block almost everything. I flushed them so the Security List is the single source of truth:
```bash
sudo iptables -P INPUT ACCEPT
sudo iptables -F INPUT
sudo apt-get purge -y netfilter-persistent iptables-persistent
```

**Problem:** `ifconfig.me` in my browser showed an IPv6 address, but the rule needed IPv4.

**Fix:** `curl.exe -4 ifconfig.me` in PowerShell forces IPv4.

## 4. Installing T-Pot
```bash
sudo apt update && sudo apt -y upgrade && sudo reboot
env bash -c "$(curl -sL https://github.com/telekom-security/tpotce/raw/master/install.sh)"
```
Chose the **Hive** install type, created a web user, and rebooted.

**Problem:** When I tried to log in, `ssh` gave `Connection refused`.

**Fix:** I was connecting to my *home* IP (the one I used in the firewall rule) instead of the server's public IP. Lesson: the server IP is what you connect to, and the home IP is what the firewall trusts.

**Problem:** The installer failed with `python3-debian is not installed` while adding the Docker repository. It also logged `hwclock: not found` (ignored).

**Fix:**
```bash
sudo apt install -y python3-debian util-linux-extra
```
Then I re-ran the installer, and it finished with 0 failures.

After install:
- Admin SSH moved to **port 64295** (port 22 is now the Cowrie honeypot)
- Web dashboard at `https://SERVER_IP:64297`
- `sudo docker ps` showed every honeypot container running
- The browser certificate warning is expected (self-signed cert)

## What I learned
- Cloud network security: two firewall layers, least-privilege admin access
- Linux administration over SSH, patching, and reading installer errors
- Verifying vendor documentation instead of trusting old tutorials
- How quickly an exposed server gets attacked (see the findings log)
